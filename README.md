# Авито Тамагочи

MVP виртуального питомца, который развивается от полезных действий пользователя на классифайде и открывает персональные бонусы Авито.

## Пользовательский сценарий

1. Пользователь регистрируется и получает питомца.
2. Действия изменяют состояние питомца и начисляют опыт.
3. Опыт повышает уровень и открывает персональные награды.
4. WebSocket, лидерборд и ежедневная сводка показывают прогресс и мотивируют вернуться.

Точные правила игры описаны в [игровом дизайне](docs/game-design.md).

## Стек

- Frontend: React 19, TypeScript, Vite, ESLint, Caddy.
- Backend: Go 1.26, стандартный `net/http`.
- Data: PostgreSQL 18.
- Infrastructure: Docker Compose.

PostgreSQL выбран как единый источник истины, потому что начисление XP, завершение задания и выдача награды должны фиксироваться атомарно. Транзакции, внешние ключи, `UNIQUE` и `CHECK` защищают игровой прогресс от частичных обновлений и повторной выдачи наград без дополнительной инфраструктуры.

## Запуск

Требуется Docker с Docker Compose.

```bash
cp .env.example .env
docker compose up --build
```

- Приложение: <http://localhost:3000>

```bash
docker compose ps
docker compose down
```

### Production HTTPS

Для запуска на домене укажите в `.env`:

```dotenv
SITE_ADDRESS=tamagochi.example.ru
FRONTEND_PORT=80
FRONTEND_HTTPS_PORT=443
APP_SECURE_COOKIES=true
```

DNS-запись домена должна указывать на сервер, а входящие TCP-порты `80` и `443` и UDP-порт `443` должны быть открыты. Caddy автоматически получает и продлевает TLS-сертификат. Сертификаты и ключи хранятся в Docker volume `caddy_data`; не удаляйте его при обновлении приложения.

## Проверки

```bash
cd backend && go test ./...
cd frontend && npm run lint && npm run build
cd backend && golangci-lint run ./...
```

Backend-конфигурация линтера находится в `.golangci.yml`. Помимо стандартного набора включены `gosec`, `misspell`, `revive`, `unconvert` и `unparam`: они проверяют безопасность, опечатки, стиль и лишний код. Frontend использует ESLint из `frontend/eslint.config.js`.

## Архитектура и ограничения MVP

- Приложение остаётся модульным монолитом; единственной публичной точкой входа служит Caddy.
- HTTP API доступен под `/api/v1`, WebSocket — под `/ws`; полный контракт находится в `api/openapi.yaml`.
- Игровые изменения выполняются синхронно в PostgreSQL-транзакциях. Redis, очереди, cron и фоновые начисления не используются.
- Действия Авито и применение бонусов являются mock-операциями; реальной интеграции с классифайдом и промокодами нет.
- Локальный и доменный deployment обеспечены Docker Compose; Caddy автоматически настраивает TLS для домена. Внешний secret storage, резервное копирование и production-мониторинг в MVP не настроены.

## Использование ИИ

Генеративный ИИ использовался для аудита требований, подготовки тестовых сценариев и проверки согласованности backend-контрактов с OpenAPI и документацией. Результаты проверялись запуском Go-тестов, Compose-конфигурации и изолированных live-сценариев; решения о публикации изменений и production deployment остаются за разработчиками.
