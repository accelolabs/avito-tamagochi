# Использование ИИ

Для прозрачности отметим, что этот документ также ведётся с помощью ИИ: по итогам диалога мы уточняем формулировки и добавляем новые пункты. Документ служит не только журналом использования ИИ, но и формой рефлексии над принятыми решениями.

## Для чего использовался ИИ

### ChatGPT / Codex

- Сравнение PDF-кейсов и повторная проверка обязательных требований кейса № 1.
- Обсуждение продуктовой идеи: игровой цикл, прогрессия питомца, задания, награды, ежедневная сводка, лидерборд и возможное применение ML.
- Критика идей и сокращение объёма проекта до MVP, который реально собрать за несколько дней.
- Выбор простой архитектуры: модульный Go-монолит, PostgreSQL, React, Nginx и единый Docker Compose.
- Пошаговые объяснения по инициализации репозитория, frontend/backend, Git-веткам, Gin, cookies, REST и WebSocket.
- Разбор кода авторизации, написанного участником команды, и объяснение Git diff.
- Совместное проектирование API: Codex задавал вопросы по эндпойнтам и моделям, предлагал варианты и указывал на лишнюю сложность; окончательные решения принимались человеком.
- Непосредственное создание и последующее упрощение `api/openapi.yaml`, а также синхронизация нового контракта с `README.md`.
- Редактирование `AGENTS.md`, `architecture.md`, `LLMUSE.md` и отдельных формулировок документации.

### Gemini

- Веб-поиск примеров геймификации и генерация набора продуктовых механик.
- Черновой вариант API, который команда не приняла без проверки и переработала вручную вместе с Codex.

Результаты обеих систем использовались как черновики и предмет обсуждения. Требования сверялись с PDF-кейсом, предложения сокращались под сроки хакатона, а изменения в репозитории проверялись человеком.

## Формат работы

- Длительный диалог с последовательным уточнением требований и решений.
- Часть команд и кода участники писали вручную, чтобы понимать устройство проекта.
- По явному запросу Codex самостоятельно вносил точечные изменения в репозиторий.
- Проверка результата через Git diff, сборку, линтеры, тесты и Docker healthchecks.
- Каждый AI-результат рассматривается как предложение и проверяется человеком.

## Планируемый ИИ в продукте

- Семантический профиль активности выбирает внешний вид и украшения питомца из разрешённого каталога.
- Backend валидирует и сохраняет результат; ИИ не рассчитывает XP и реальные награды.
- Не передаются пароли, переписки и контактные данные.
- При недоступности модели используется детерминированный fallback.

Runtime-интеграция ИИ пока не реализована.
