# Игровой API

Полный контракт находится в `api/openapi.yaml`. Игровые endpoints требуют cookie `session_id`.

## REST

| Метод | Endpoint | Результат |
| --- | --- | --- |
| `GET` | `/api/v1/pet` | Получить или создать питомца. |
| `POST` | `/api/v1/pet/actions` | Выполнить JSON-действие `"charge"`. |
| `GET` | `/api/v1/tasks/today` | Получить три задания московского дня. |
| `POST` | `/api/v1/mock-avito/actions` | Выполнить `view`, `favorite`, `create_listing` или `create_listing_in_category`. |
| `GET` | `/api/v1/rewards` | Получить награды пользователя. |
| `POST` | `/api/v1/rewards/{rewardID}/use` | Использовать награду. |
| `GET` | `/api/v1/summary/today` | Получить сводку московского дня. |
| `GET` | `/api/v1/streak` | Получить текущую и рекордную серию и следующую дневную награду. |
| `GET` | `/api/v1/leaderboard` | Получить top-10 по общему XP. |
| `GET` | `/api/v1/leaderboard/week` | Получить top-10 по дельте XP за последние 7 × 24 часа. |
| `GET` | `/api/v1/leaderboard/month` | Получить top-10 по дельте XP за последние 30 × 24 часов. |
| `GET` | `/api/v1/leaderboard/streak` | Получить top-10 по активной серии. |

## Поведение

- Первая зарядка за московский день восстанавливает 100% энергии, даёт 10 базовых XP и дневную награду от 10 до 50 XP по текущей серии. Повторная зарядка возвращает состояние и нулевые начисления.
- Энергия линейно уменьшается до 0 за 48 часов после успешной зарядки.
- После пропуска полного московского дня текущая серия равна нулю. Рекордная серия сохраняется.
- Через 48 часов без зарядки питомец умирает. Сбрасываются текущие XP, серия и доступные награды; история XP, рекорд серии, использованные награды и прогресс заданий сохраняются.
- Зарядка оживляет умершего питомца. Попытка выполнить его задание возвращает `409 pet_dead`.
- Пять `view` завершают задание просмотра; остальные задания завершаются одним действием.
- Недоступное сегодня действие возвращает `400 task_not_available`.
- Завершённое задание не меняется при повторном действии.
- Уровень и стадия вычисляются из XP и не хранятся отдельно.
- Награды создаются для каждого достигнутого уровня начиная со второго и используются один раз.
- XP, прогресс задания и новые награды записываются в одной транзакции.
- Московский день — интервал от `00:00` включительно до следующего `00:00`.
- Общий лидерборд сортируется по `xp DESC, user_id ASC`.
- Недельный и месячный лидерборды используют скользящие UTC-интервалы 7 × 24 и 30 × 24 часов и сортируются по `xp_delta DESC, user_id ASC`.
- Лидерборд серий сортируется по текущей серии, дате её начала и `user_id`.

## Тестовые данные

Сидирование не является HTTP API. Оно запускается отдельно и создаёт десять служебных пользователей, заполняющих все четыре лидерборда:

```bash
docker compose run --rm seed
```

Повторный запуск обновляет только служебные записи и не изменяет данные обычных пользователей.

## WebSocket

```http
GET /ws
```

После успешного commit backend отправляет одно из событий:

```json
{"event":"pet_updated"}
{"event":"tasks_updated"}
{"event":"rewards_updated"}
```

Данные в событие не входят: frontend повторно запрашивает REST API.
