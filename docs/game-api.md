# Игровой API

Все endpoints требуют session cookie, если не указано обратное. Ошибки API используют общий `ErrorResponse` из `api/openapi.yaml`.

Все игровые endpoints подключены к отдельным доменным сервисам. PostgreSQL остается единственным источником состояния.

## REST-эндпойнты

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `/api/v1/pet` | Получить или создать питомца текущего пользователя. |
| `POST` | `/api/v1/pet/actions` | Принять JSON-строку `"charge"`, восстановить заряд и начислить дневной XP. |
| `GET` | `/api/v1/tasks/today` | Получить три задания текущего московского дня. |
| `POST` | `/api/v1/mock-avito/actions` | Принять `"view"`, `"favorite"`, `"create_listing"` или `"create_listing_in_category"`. |
| `GET` | `/api/v1/rewards` | Получить награды пользователя. |
| `POST` | `/api/v1/rewards/{rewardID}/use` | Однократно использовать доступную награду. |
| `GET` | `/api/v1/summary/today` | Получить сводку текущего московского дня. |
| `GET` | `/api/v1/leaderboard` | Получить top-10 пользователей и позицию текущего пользователя. |

## Основное поведение

- Заряд питомца backend рассчитывает по `lastChargedAt`; frontend может плавно анимировать его локально.
- `charge` начисляет 10 XP один раз за московский день.
- Пять действий `view` закрывают задание просмотра. Остальные mock-действия закрывают соответствующее задание одним вызовом.
- Выполненные задания и использованные награды не дают XP или бонус повторно.
- XP, уровень, прогресс заданий и изменения наград сохраняются в одной транзакции.
- Текущий день — интервал `[00:00, 00:00)` в timezone `Europe/Moscow`.
- Сортировка лидерборда: `xp DESC, user_id ASC`.
- Награда создается один раз при пересечении уровня и может быть использована один раз.

## WebSocket

```http
GET /ws
```

После успешного изменения игры backend отправляет только имя события:

```json
{"event":"pet_updated"}
{"event":"tasks_updated"}
{"event":"rewards_updated"}
```

Frontend использует событие, чтобы повторно запросить данные через REST.
